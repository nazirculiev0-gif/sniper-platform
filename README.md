# SNIPER — платформа рекрутинга (MVP-скелет)

Полноценный full-stack проект на Next.js + PostgreSQL + Prisma, построенный на основе
UI-прототипа. Реализована рабочая часть основного цикла: регистрация/вход по ролям,
создание вакансии, взятие в работу рекрутером, канбан кандидатов, подтверждение
найма с автоматическим созданием эскроу-платежа и расчётом комиссии 15%, вывод
средств рекрутером, освобождение эскроу по частям (50/50) администратором через API.

## Быстрый старт

```bash
# 1. Установить зависимости
npm install

# 2. Поднять Postgres (или укажите свою БД в .env)
docker run --name sniper-db -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:16

# 3. Настроить переменные окружения
cp .env.example .env
# сгенерировать NEXTAUTH_SECRET: openssl rand -base64 32

# 4. Прогнать миграции и создать таблицы
npx prisma migrate dev --name init

# 5. Заполнить тестовыми данными
npm run seed

# 6. Запустить
npm run dev
```

Откройте http://localhost:3000 — попадёте на логин.

Тестовые аккаунты (пароль у всех `password123`):
- `employer@demo.uz` — работодатель, видит свою заявку
- `recruiter@demo.uz` — рекрутер, видит биржу, может взять заявку в работу

## Что уже работает

- Регистрация и вход (NextAuth, роли employer/recruiter/admin)
- Создание вакансии работодателем → модерация
- **Админ-панель**: `/dashboard/admin/requests` (модерация заявок — одобрить/отклонить),
  `/dashboard/admin/recruiters` (верификация рекрутеров), `/dashboard/admin/finance`
  (GMV, заработанная комиссия, таблица платежей с выплатой эскроу по частям)
- Рекрутер видит биржу открытых заявок, берёт в работу (с проверкой эксклюзивности)
- Канбан кандидатов по этапам, добавление кандидата, перемещение по этапам
- **Матчинг-скоринг**: `/dashboard/candidates` — база кандидатов рекрутера с
  автоматическим подбором лучшей подходящей открытой заявки (`src/lib/matching.ts`,
  логика перенесена и типизирована из прототипа)
- Подтверждение найма работодателем → создаётся `Payout` в статусе `IN_ESCROW`
  с расчётом комиссии платформы (15%) и датой окончания гарантии
- Освобождение эскроу по частям (50/50) администратором прямо из UI финансов
- API для вывода средств рекрутером

Важно: заявку нужно сначала одобрить в `/dashboard/admin/requests` под аккаунтом
`admin@demo.uz`, прежде чем рекрутер сможет её увидеть на бирже и взять в работу
(seed создаёт заявку сразу в статусе `OPEN`/`APPROVED`, так что демо-данные уже готовы
к работе, но новые заявки, созданные через форму, попадают в очередь на модерацию).

## Чего пока нет (следующие шаги, по приоритету)

1. **Реальный эскроу / платежи** — сейчас это статусы и суммы в БД, без движения
   настоящих денег. Для реальных денег нужна интеграция с платёжным провайдером
   (в Узбекистане — Payme/Click, либо Stripe для международных карт) и, скорее всего,
   юридическая консультация по механизму удержания средств (номинальный счёт/эскроу-агент).
2. **Чат и видеозвонки** — в прототипе есть UI, для реальной версии нужен
   Pusher/Ably/Socket.io для чата и Daily.co/Twilio/Jitsi для звонков.
3. **Загрузка и парсинг резюме (CV)** — в прототипе `CvUpload` — заглушка;
   для реального парсинга нужен либо сторонний сервис, либо LLM-парсинг PDF/DOCX.
4. **Файловое хранилище** — для резюме, логотипов компаний и т.п. (S3-совместимое,
   например Cloudflare R2).
5. **UI для перетаскивания канбана (drag&drop)** — сейчас перемещение по этапам
   идёт кнопками «Дальше →» / «Отказ», без drag&drop.
6. **Тесты и CI** — сейчас проект не покрыт тестами.
7. **Деплой** — Vercel для приложения + Neon/Supabase/RDS для Postgres.

## Структура проекта

```
prisma/schema.prisma        — вся модель данных (пользователи, вакансии, канбан, платежи)
prisma/seed.ts               — тестовые данные
src/lib/auth.ts              — конфигурация NextAuth
src/lib/prisma.ts            — синглтон Prisma-клиента
src/lib/currentUser.ts       — получить текущего пользователя с профилем
src/app/api/**                — все API-роуты (REST, JSON)
src/app/(auth)/**             — страницы логина/регистрации
src/app/dashboard/**          — авторизованная часть приложения
src/components/**             — переиспользуемые клиентские компоненты
src/app/globals.css           — дизайн-система, перенесённая из исходного прототипа
```

## Дизайн

Цветовая палитра, отступы и стили кнопок/карточек/пилюль-статусов взяты один в один
из вашего HTML-прототипа (`--red`, `--dark`, `.btn`, `.card`, `.pill-*` и т.д.),
чтобы визуально это было продолжение того же продукта, а не новый дизайн с нуля.
